# Release notes — 9 November 2026

**Release:** `2aaf327` (PR #1285, "Release 2026-11-09: Monday integration").
**What it is:** 38 pull requests merged in one release, plus 14 database migrations that run automatically on deploy. The merge record is in `docs/release/2026-11-09-merge-guide.md`; the deploy steps are in `docs/release/2026-11-09-deploy-runbook.md`.

---

## For school admins

- **Exam sets.** Create a term's exams for every class and subject in one place, then open a set to enter marks or check what is missing. Menu: **Exams and reports → Exam sets**.
- **Manage exam types.** Which exam types count toward results is now a school setting. **Settings → Exam types**.
- **Marks release.** A separate **Marks Release** page shows what is ready, who may release it, and what parents will see. Approval and release are separate steps.
- **Student import.** The **Import students** page is the one place to upload a student list. It shows skipped rows and their row numbers, and reports failures instead of stopping halfway. Old import links now open this page.
- **Class pages.** Each class has a page listing its streams, the class teacher, and the students in each stream.
- **Plan limits.** A school on a plan with a limit sees a notice when it adds more teachers or students than the plan allows. The extra rows are still saved; nothing is dropped. The **Early adopter** plan is available to platform staff for founding schools.
- **One top bar and account menu** for every role, and a password change that keeps you signed in on the device you used.
- **Country and phone data.** Country codes are corrected, and phone numbers are stored in international format.

## For class teachers

- Your home page shows your classes, today's attendance, and the marks that need you.
- You can open the attendance register for your whole class, including every stream, and save it in one go.
- The class page for your class lists each stream, its teacher, and its students.
- If you were invited by email, the invite link sets your own password. It can be resent.

## For teachers

- **Take attendance** opens a register for your class or stream with everyone marked present. Tap **Absent** for the ones who are not there, then **Save attendance**. Marking everyone present is one button.
- **Marks.** Enter marks per exam; saved marks show when you return. Release is done by the person allowed to release, not by every teacher.
- Your dashboard shows your classes and the marks that need attention.

## For parents

- The parent portal shows released results, attendance and fees for each linked child.
- Attendance uses half days: both sessions present is a full day, one session is a half day.
- Fees show the term structure, what is paid, the balance, and the year total.
- Nothing is shown for a term that has not been released.

## For students

- The student portal shows released results, attendance and fees in the same way, for the signed-in student only.

## Fixed in this release

- A marks release page could fail for a class teacher when classes were ordered by level; the query now names the right table.
- Two pull requests added the same country constant, which stopped PHP from starting; the duplicate is removed.
- Student and teacher imports now report the rows they skip, with row numbers.
- The teacher home page keeps the marks tiles and the Marks Release link inside the new layout.
- Country codes and international phone numbers are corrected and stored consistently.
- The parent and student sidebars use the same shell as every other role, so the footer and menu no longer drift.
- The class marks picker and the class list now follow the same level-then-stream order.

## Known, and coming

- **Attendance double save.** Saving the same register twice in a row is a known risk. Until it is fixed, save once and wait for the confirmation line before leaving the page.
- **Page speed.** Some pages are slow on large schools, especially lists with many students. Work on this is queued; it is not in this release.
- **Uploaded files on the server disk.** Photos, imports and generated files are only safe if the app uses the cloud storage disk. If `FILESYSTEM_DISK` is `local`, files are lost on the next deploy (`docs/release/2026-11-09-deploy-runbook.md`, rollback table). Check the disk setting before uploading real photos.

## Notes

- Fourteen migrations run on deploy. Take a database backup first; the runbook has the order and the rollback for each one.
- This release does not change what a school can configure; it adds pages and fixes behaviour.
