## Pre-demo checklist

### Data that must exist beforehand

- [ ] **Two classes, on purpose.** Class A is the live class: its exams do not exist yet, so step 1 creates them. Class B is the safety net: marks entered, approved and **released** before the demo (see fallbacks). Check both are base classes, not streams.
- [ ] **Released marks for at least one class** (Class B). Steps 7 and 8 need a released sitting to show anything: the parent's Grades page and the profile's Performance card list released results only. With nothing released they read "No results published" and "No released results yet".
- [ ] **A term for the exam set**: the current term exists under Academic year (step 1 lists terms; with none it says "No academic terms yet").
- [ ] **A parent with a reachable child**: the parent login is linked to Aaron Ahimbisibwe (link it from the parent's profile under Parents), and Aaron is enrolled in a class that has a released sitting. Open `/parent/children` as the parent to confirm the child is listed.
- [ ] **A student photo**: Aaron has a photo uploaded already, so the ID card shows a picture without waiting on an upload. Keep one more JPG or PNG under 2 MB on the desktop for the live replace. [#1274] On a local preview the photo needs `FILESYSTEM_DISK=public` and `php artisan storage:link`, or it uploads and then shows a broken image.
- [ ] **Fees**: a Tuition row for Aaron's class and term (Fees → `/admin/fees-categories`; #1270 makes it one whole-school row) and one part payment recorded, so the balance is not zero. "Mark as paid" is hidden at zero. [#1274]
- [ ] **One AB and one over-100 row planned**: pick two students in Class A and write their names down. One will be typed `AB`, the other `105`.
- [ ] **Queue worker running** (or the sync queue). The whole-class report PDF in step 5 is built by a queued job; with no worker it stays on "Preparing".
- [ ] **WhatsApp off.** On the release screen, "Send these results on WhatsApp" is off by default and stays off. Nothing goes to a real phone.
- [ ] **Currency is UGX** for the demo school (profile and dialog text read "UGX 300,000").

### Reset between rehearsals

Rehearse the whole story twice, resetting each time.

1. **Reset the demo school to its seeded baseline** with `php artisan demo:reset {school} --dry-run` and then `php artisan demo:reset {school}` (one demo school; it will not touch a real school). `demo:refresh {school}` does the same for staging and keeps accounts and password hashes. These remove everything made after the seed, including the exam set, marks, releases and Mark as paid payments.
2. **Re-create the prepared state** the reset removes: the Class B released sitting, Aaron's part payment and photo, and the parent link. Keep these as a short seed script or a database dump you can restore in one step. Restoring a dump is faster than re-clicking.
3. **Confirm in this order**: Class A has no exam set for the term; Class B shows as released on `/admin/marks/releases`; Aaron's balance is above zero; the parent sees Class B results.
4. Delete the test photo you uploaded live, or leave it; it does not affect the next run.

## The steps

### 1. Admin creates the term's exam set (1:00)

- **Signed in:** school admin. **Screen:** Exam sets → New set, `/admin/exams/sets/create`. **[#1272 stack]** (create is #1261; the set page and filters are #1272).
- **Clicks:**
  1. Sidebar: **Exams and reports → Exam sets → New exam set**.
  2. Pick the **Term**.
  3. Leave the default **Exam types** ticked (or tick one, for example Mid Term).
  4. Tick **Whole school**. Leave **Pick specific streams instead** alone.
  5. Click **Create exam set**. A "Creating this term's exams…" line shows for a few seconds.
  6. You land on the set page, `/admin/exams/sets/{id}`.
- **Audience sees:** the set page headed "{term} exams", counts of classes, exams in this set, exams with marks, and subjects with no teacher, then a Filters panel (type chips, Class) and one block per class listing its subjects.
- **Say:** "One click creates every exam for the term, for every class and subject. Teachers see their own exams straight away."
- **Note for the presenter:** "Whole school" creates exams on the **base classes only**, never their streams (code: `ExamSetService::baseSectionIds`). The on-screen helper text under the checkbox says "every class and stream". Don't read it out; it is wrong about streams.
- **If it fails:** open the existing set for Class B from **Exam sets** and present that page instead. On `main` alone there is no set page; use **Exams and marks → New exam** at `/admin/exams/add-new` (one exam at a time) and say so.

### 2. Class teacher enters marks and submits (2:00)

- **Signed in:** class teacher. **Screens:** `/teacher/exam/marks` (**Marks** in the sidebar, "Your exams to mark") then `/teacher/exam/{exam}/marks/enter`. Entry itself is **[main]**. The "Type AB" hint, the over-100 warning, the stream filter and the "create this term's exam set" nudge are **[#1272 stack]**.
- **Clicks:**
  1. **Marks** → on the exam for Class A, click **Enter marks**.
  2. Point at the hint under the title: "Type AB when a student was absent. Marks are out of 100."
  3. Type marks down the column. On the planned absent student type `AB`. On the planned slip type `105`.
  4. Click **Save draft**.
  5. The row with 105 now shows a red **"Above 100. Check the mark."** under it. Correct it to a valid mark and **Save draft** again.
  6. Click **Submit for review**.
- **Audience sees:** the marks grid, the AB row stored as absent, a red warning on the over-100 row, then the exam showing as submitted in the list.
- **Say:** "Absent is AB, a mistake above 100 is flagged, and the teacher submits when it is right. Nothing reaches parents from here."
- **Presenter note:** the above-100 message is a warning, not a block. The mark is saved as typed (`ExamMarkWriter` does not reject it), so correct it on screen before submitting.
- **If it fails:** jump to Class B's exam, already filled and submitted, and say "here is one that is done". Or the teacher's **Paste or upload marks** link on the teacher's exams list if typing is slow.

### 3. Admin approves in bulk (1:00)

- **Signed in:** school admin. **Screen:** Mark submissions, `/admin/marks/submissions`. The page and per-subject **Approve** are **[main]**; the tick-boxes and bulk **Approve N** are **[#1272 stack]**.
- **Clicks:**
  1. Sidebar: **Exams and reports → Mark submissions** (the page title is "Marks", tab **Approvals**).
  2. The header says "N awaiting review". Tick the boxes for the submitted subjects of Class A.
  3. Click **Approve N** (the number follows your ticks).
- **Audience sees:** the table (Subject, Class, Teacher, Term, Type, Submitted, Approval), the count going from pending to approved.
- **Say:** "The admin checks what teachers submitted and approves it in one go."
- **If it fails (or on `main`):** click **View Details** on each submission and approve it there (`/admin/marks/submissions/{exam}`); it is slower, so approve two and say "and the rest the same way". Class B is already approved.

### 4. Admin opens the combined mark sheet (0:45)

- **Signed in:** school admin. **Screen:** Mark sheets, `/admin/marks` (also `/admin/marks/filter`). **[#1272 stack]** (combined sheet is #1242; `main` has the older class overview at the same address).
- **Clicks:**
  1. Click the **Mark sheets** tab beside Approvals.
  2. Choose **Class A**, the **term**, and the **exam type**.
  3. Point at the heading ("End of term marks" or the type name), "All marks saved", and **Download sheet**.
- **Audience sees:** one grid, every student against every subject, with the absent student shown as AB. If a subject is missing marks, a banner says so: "N subject(s) still missing marks… Publishing now would send incomplete report cards to parents."
- **Say:** "Every subject for the class on one sheet, so the admin can see nothing is missing before anything is released."
- **If it fails:** open Class B in the same screen (all subjects present). With no exams at all the page shows "No exams yet: create this term's exam set."

### 5. Admin generates report cards: one student, then the whole class (1:15)

- **Signed in:** school admin. **Screen:** Report cards, `/admin/reports/cards`. **[#1274]** (on `main` the older per-term page is at the same address; after #1274 it moves to `/admin/reports/cards/history`).
- **Clicks:**
  1. Sidebar: **Exams and reports → Report cards**. Choose **Class** and **Exam** (a sitting). The page says "Built from released marks only".
  2. One student: click **PDF** on a row (route `/admin/reports/cards/{stdLink}/student/{learner}/download?term={id}`). The card downloads.
  3. Whole class: click **Build all N cards (one PDF)**. The page shows "Preparing N report cards…", then **Download all N cards (one PDF)** when ready. Click it.
  4. On a phone, show **Filters**: Class, Exam, Stream and Sort collapse into a bottom sheet.
- **Audience sees:** KPIs (cards ready, class average, Division I, ungraded), Average by subject, Students by division, then the positions table with a PDF per student.
- **Say:** "One card for one child, or the whole class as a single PDF to print."
- **Order problem, decide before Thursday.** The story puts report cards before release, but this screen only lists a sitting once it is released (it is "built from released marks only", as the design says). If Class A is not released yet, the page shows "{Class} {Exam} isn't released yet" and no marks. Pick one:
  - **Recommended: swap steps 5 and 6.** Release Class A, then generate the cards. Narrate it as "marks are out, now the printed cards".
  - **Or keep the order** and run step 5 on **Class B**, which is already released, saying "same thing for a class that is already released".
- **Whole-class PDF, which path:** [#1274] builds it through the existing queued job (`/admin/reports/cards/merged/{stdLink}`). [#1271] adds a direct download for classes of up to 12 students on the **teacher's** report cards page (`/teacher/reports/cards/{stdLink}/pdf`) and does not rewire the admin button. Use the admin button in the demo; mention #1271 only if asked.
- **If it fails:** the single-student PDF is the safe fallback. If "Preparing" does not finish, the queue worker is not running: say "this builds in the background" and download the PDF you built in rehearsal (`/admin/reports/cards/history` lists earlier PDFs).

### 6. Admin releases with the checklist and audience panel (1:15)

- **Signed in:** school admin. **Screen:** Release marks, `/admin/marks/releases/new`, then the confirm step, then `/admin/marks/releases/{id}`. Releasing is **[main]**. The checklist, the audience panel and the "Why release again?" prompt are **[#1272 stack]**. The sidebar label reads "Release marks", and "Marks Release" once #1269 is in.
- **Clicks:**
  1. Sidebar: **Exams and reports → Release marks** (or the **Marks Release** tab on the sheet).
  2. Read the three steps: **1 All subjects approved** (shows "N of M approved"), **2 Preview**, **3 Release** ("Families are told only from this step").
  3. Point at **Who will be told**: per class "N parents · N on WhatsApp", and the total. It says it is only a count and nothing is sent until you release.
  4. Choose the **Exam** and **Class** (Filters on a phone). Leave **Release now**. Leave **Send these results on WhatsApp** unticked.
  5. Click the release button (it reads "Release to {class}"). The preview shows "Send these marks?" with the message.
  6. Click **Confirm and release**. The result page opens.
- **Audience sees:** a clear three-step checklist, a count of who would hear about it, and a confirmation before anything happens.
- **Say:** "Release is deliberate: every subject approved, a preview, and a count of who will be told. Parents are never messaged until this step."
- **If it fails:** open Class B's release (`/admin/marks/releases`) and show its result page. If step 1 is not complete, return to step 3 and approve the missing subject. A sitting released before asks "Why release this sitting again?" and needs a reason, so type a short one.

### 7. The parent's view (1:15)

- **Signed in:** parent (separate window). **Screens:** Dashboard `/parent/dashboard`, Children `/parent/children`, Grades `/parent/children/{student}/grades`. Grades is **[main]**. Showing **all** released results with linked stats is **[#1266]**.
- **Clicks:**
  1. **Children** → pick Aaron → **Grades**.
  2. Show the released sitting (Subject, Score, Grade). Open **Fees** and **Attendance** from the sidebar if time allows.
- **Audience sees:** only what was released: the sitting from step 6 for the released class. The parent never sees draft, submitted or unapproved marks.
- **Say:** "This is the parent's side: results appear here the moment the school releases them, and not before."
- **If it fails:** Class B is released already, so the parent always has something. If the parent sees "No results published", the link between parent and Aaron is missing or Aaron is in a class with nothing released; sign in to the spare admin window and go to step 8.

### 8. Student profile: ID card, performance, fees, Mark as paid (1:30)

- **Signed in:** school admin (second window). **Screen:** Student profile, `/admin/students/{id}`. **[#1274]** (the profile exists on `main`; the ID-card photo, Performance card, Fees card, and "Mark as paid" are #1274).
- **Clicks:**
  1. Students → **All students** → Aaron Ahimbisibwe.
  2. **ID card:** point at the photo (square crop), the student number, class, date of birth and **Joined**. Click **Change photo** and choose a JPG or PNG under 2 MB; **Replace photo** saves it. (With no photo it shows initials and **Add photo**.)
  3. **Performance** card: the released average and the PDF list; the **Download current progress report** button appears only when there are approved marks that are not released yet, labelled as not released.
  4. **Fees · {term}**: show "UGX … still owed" and the bar.
  5. Click **Mark as paid**. The dialog reads "Record UGX {balance} as paid for {term}?" with **Paid by** set to Cash. Click **Record UGX {balance}**.
  6. The Fees card now reads "UGX 0, nothing owed", and **Mark as paid** is gone.
  7. On the phone-width window: the same page with the compact card and the dialog as a bottom sheet.
- **Audience sees:** a photo on the card, released results only on Performance, and the balance cleared by one confirmation.
- **Say:** "Everything about one student on one page: their photo, their released results, and the fees, which the admin can settle with one confirmation."
- **If it fails:** if the photo is broken, the storage link is missing (see the checklist); show the initials avatar instead. If **Mark as paid** is missing, the balance is already zero: use **Record a payment** with a part amount, or pick a student whose fees are not cleared. Do not run it twice on the same student in the demo; the second time the button is gone.

## Fallbacks in one table

| Problem | Do this |
|---|---|
| Exam set page missing (not on `main`) | Show Class B's existing set; or `/admin/exams/add-new` for one exam |
| Typing marks is slow | Use **Paste or upload marks** on the teacher's list, or jump to Class B's filled exam |
| Bulk approve missing | Approve two submissions one at a time from **View Details**; say "and the rest" |
| Combined sheet missing | Use the class overview at `/admin/marks`, or Class B |
| Class PDF stuck on Preparing | Queue worker is off. Download the PDF from rehearsal, or a single student's **PDF** |
| Report cards screen says "isn't released yet" | Release first (step 6, so swap 5 and 6), or use Class B |
| Parent sees "No results published" | Parent link or release is missing; skip to step 8 |
| Photo is broken | `FILESYSTEM_DISK=public` plus `php artisan storage:link`; or show initials |
| Anything breaks hard | Say "this is the part we are finishing" and move to the next step; every step stands alone |

## What not to claim on stage

- Don't call the whole-class PDF instant: it is built in the background.
- Don't promise WhatsApp delivery. WhatsApp sending is off by default on the release screen, and a real send also waits for Meta's approval of the `results_released` template.
- Don't say "Whole school includes streams": it creates exams on base classes only.
- Don't say Mark as paid sends a receipt. No receipt is sent.
- The photo is not shown in the report cards PDF; only on the profile.
