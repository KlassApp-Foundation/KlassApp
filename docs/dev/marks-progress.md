# Marks and reports progress

Handover for any later session. Updated after each numbered item. Draft only: no merges, no deploys.

This file is [#1328](https://github.com/KlassApp-Foundation/KlassApp/pull/1328) on `marks/progress`.

**Decisions (final, 2026-11-11, composition restated 2026-11-13).** Class teachers keep creating exam sets for their own class, and can approve or return marks for that class. Head teachers have the same powers as a school admin inside their own school, never across schools. Admins and head teachers can enter, save, submit, approve, return and release for any class. Subject teachers enter, save and submit their own subjects. Each exam set has its own report when it is released. A school names its own sets, any number, in date order. "Beginning of Term", "Mid Term", and "End of Term" are starter defaults only. For one combined report per term, a set either counts toward that mark with a weight (the counting weights total 100) or stands alone with no weight. Storage can hold another combined report later. A missing mark and ABS both count as 0. Missing is shown as "Missing". ABS is shown as ABS. A released report does not change when the setup changes. Parents and learners see marks and report cards only after release. The earlier "incomplete" state and "use the sets this learner sat" are closed.

**Where this work lives.** New work goes in its own worktree from `origin/main` (`2aaf327b`), with its own database and a port other than 8000 or 8126. The demo on `poc/toshi-checklist-onboarding` at tag `demo-final-2026-11-11d` stays untouched. The design handoff is at `~/Downloads/marks-handoff/` (`HANDOFF.md` wins over the drawings). Section 5 now has seven screens. The two questions at the end of that section are closed: a missing mark counts as 0 and is labelled Missing, and ABS counts as 0 and is labelled ABS. A counting set with marks entered but not released still blocks that class's combined report.
