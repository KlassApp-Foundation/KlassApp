What changed, and what is verbatim

Verbatim from the real files

Structure, ids, classes, role order and all copy are verbatim from landing-v2.blade.php — with two deliberate deviations, both listed in the flags below: #heroRoleStage → #heroRoleDeck[data-auto="1"] → three article.hero-role-card (.wa/.drive/.slack, data-role parent/teacher/admin), then #heroRoleDots and .connector-float. The Email/SMS/Calendar inline SVGs are real Blade source (lines 118–120), lifted as-is.

Card geometry and colour are unchanged: inset 12px 18px, radius 22px, #0B1220, the two-part box-shadow, and the three header fills #075E54 / #1E3A5F / #3F1F5C. Bubbles, rows, meta and dots are lifted as-is — as are the paper layers (all four ::before background layers, the feTurbulence grain at opacity .22 with mix-blend-mode:multiply, and the .hero-deckle torn-edge SVG) and the stage float.

Reduced motion — two real guards, both verbatim

The real file ships two prefers-reduced-motion blocks touching this hero, both kept exactly:

  • The component block (528–537): transition:none !important, transform:none !important — an instant swap, no fade, no rotation, body stagger off, dots hidden.
  • A separate guard at line 2349 killing .hero-stage's float animation.

Still the only place in the codebase that guards reduced motion — the app stylesheets have none.

The stage floats — it composes with the flip

.hero-stage{animation:float 6s ease-in-out infinite} at line 2348 drifts the whole stage −8px and back, continuously. Kept verbatim.

This matters for the specced transition: the card flips on X while its container is already moving on Y, so the two read together. Judge the flip timing with the float running, not against a static stage.

The connector-float overlap is desktop-only

.connector-float overlaps the message bubbles above 900px. That is real CSS: the generic rule sets right:-32px, and .hero-preview .connector-float overrides to right:-28px; top:42%; z-index:5. At a 360px preview a 180px panel inset by −28px covers roughly a third of the card.

Production hides it entirely at ≤900px — the real breakpoint carries both .hero-preview .connector-float{display:none} and .connector-float{display:none}. That block is now in place, so the overlap disappears below 900px exactly as production does. Left alone on desktop rather than “fixed”, but worth a look since the flip draws the eye there.

Resolved — avatar ruling B, applied

The K mark now sits on all three cards, replacing KA / DR / #, per the established principle that K is Toshi's persistent bot identity across whatever tool the user is in — a profile picture, not a “who sent this” indicator. .hero-role-avatar is redefined to mirror .toshi-pill-avatar: 38px circle, transparent fill, 1px var(--brand-green) ring, 24px mark.

Two consequences to carry into Blade, both accepted:

  • The header grows 56px → 66px (measured), taking 10px from every card's body inside the fixed 420px stage. Visible in the before/after tiles above. No stage height change was made to compensate — flag if the tighter body area reads badly on the Drive card, which has the most rows.
  • The three headers are now distinguished only by fill colour and label — #075E54 / #1E3A5F / #3F1F5C plus “Parent · WhatsApp” etc. The per-tool glyph cue is deliberately gone; the coloured bar carries it alone.

The real Blade rule (28px, rgba(255,255,255,0.18), text initials) is superseded — this is an intentional divergence from current production, not a fidelity miss.

Other conflicts with the spec, flagged not reconciled

  • --d-transition-slow does not exist in landing-preview.css. That file defines its own --brand-* / --paper-* set and no --d-* tokens at all. I declared --d-transition-slow:0.3s ease locally to honour the spec literally, but on the real page you either add the token to :root or write 0.3s ease inline. Flagging rather than assuming the design-system token sheet is loaded there.
  • The spec said perspective:900px; the real stage already has 1400px. Real value wins — no change made.
  • The rotation JavaScript was not in either file. #heroRoleDots ships empty in the Blade and is populated at runtime, and nothing in landing-v2.blade.php references heroRoleDeck, is-exit or data-auto. So the driver lives in a JS file I have not seen. The script here is my reconstruction against the real class contract (.is-active / .is-exit, data-auto, dot .on) — compare it against the real one before replacing it; the timing constants especially (I used a 3.2s hold).
  • No avatar exists anywhere in .hero-role-body. The real bubbles are bare — no per-message avatar slot. So "the Toshi avatar throughout" has no existing home in the message list; adding one would be new markup, not a substitution. Not done.
  • Dropped reveal reveal-delay-2 — do not “restore” these. The real element is <div class="hero-preview reveal reveal-delay-2"> (line 78). landing-preview.css:57 sets .reveal{opacity:0;transform:translateY(24px)}, and only .reveal.visible reveals it — via an IntersectionObserver living in JS that was not in either file supplied. Keeping the classes here would render the entire hero preview invisible. Restore them in Blade only together with that observer — and note this means the reveal animation was not cut from production.
  • Brand marks are <img>, not Blade components. Real source uses <x-brand.whatsapp />, <x-brand.google-drive />, <x-brand.slack /> (lines 115–117). A static page cannot render Blade, so these point at the real extracted SVGs in assets/brand/. Put the components back in Blade.
  • Reduced motion: real behaviour kept, verbatim. Lines 528–537 set transition:none !important — an instant swap with no fade. The spec had asked for a cross-fade; ruled in favour of the real code, so this is now byte-for-byte the shipping block. Nothing to change in Blade.
  • Two small omissions now restored: .connector-icon has a real transition plus a :hover{translateY(-2px); box-shadow:var(--shadow-sm)} lift (lines 712–716) that my first pass dropped, and I had added a flex-shrink:0 to .hero-role-avatar that does not exist in the real rule — removed.
  • Box-sizing: good news — landing-preview.css line 1 is *,*::before,*::after{box-sizing:border-box}. The hero is unaffected by the reset gap found in the app bundle. Measurements below are with that reset in force, as production has it.
