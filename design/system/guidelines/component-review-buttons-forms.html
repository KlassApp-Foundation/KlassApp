Buttons — the real variants

The codebase ships six: primary, success, danger, warning, outline, ghost. There is no "secondary" — .ds-btn-secondary appears only in the touch-target selector list and has no rule of its own. Outline is the de-facto secondary.

Two real contrast failures, same bug as the --d-accent fix

Success and warning put white text on the bright brand hues — exactly what the 2026-09-18 --d-accent fix corrected for primary, but those two variants were missed. Warning has a clean fix (its own hover colour #B45309 is already --d-warning). Success had no distinct fix — the only AA-passing green is #15803D, which is primary. Decided 2026-09-27: success is retired as a button variant.

Sizes & the 44px touch target

The three contract-tested sizes, measured live with getBoundingClientRect. The touch-target rule sets min-height: 44px on every .ds-btn, so the minimum is met at all sizes — including sm.

measuring…

Consequence worth knowing: because 44px wins over padding, sm and md render at the same height — sm is only narrower (12px vs 18px side padding) with smaller text (0.78rem vs 0.85rem). That's the correct trade for a school app used on phones, so I've kept it. If a genuinely compact button is ever needed (dense table toolbars on desktop), the honest route is a @media (pointer:fine) exception — not shrinking the minimum globally.

Loading — new, designed to the existing motion rules

Anatomy

14px ring, 2px stroke in currentColor so it inherits every variant's text colour with no per-variant rule. Prepended with the existing 6px gap. The label stays ("Save" → "Saving"), so the button never changes width and nothing in the row reflows. aria-busy="true", pointer events off, cursor: progress.

Motion

0.7s linear infinite rotation. Under prefers-reduced-motion the ring stops and closes to a static 55%-opacity circle — the label change carries the state. This makes it the sixth infinite loop in the system, so it joins the reduced-motion coverage list in DESIGN_SYSTEM.md.

Responsive behaviour
