Empty & loading states

These are the general versions of what Tables introduced. .dt-skel and .dt-busy are now aliases of .ds-skel / .ds-busy in styles/feedback-v2.css, and Charts reuse the same pieces below. Everything extends the real .ds-empty-state and .ds-loading-dot rules instead of replacing them.

Which loading treatment — decided by what's already on screen

SituationUseWhy
Nothing shown yet (first load).ds-skel placeholders shaped like the contentThe layout appears at once and doesn't jump when data lands. It reads as "almost here", not "broken".
Content shown, being refreshed.ds-busy — a 2px blue bar across the topNever blank out data the user is reading. The rows stay put, and the bar says an update is on the way.
User pressed a button.ds-btn.is-loadingThe feedback belongs where they clicked. The label stays, so the width is stable.
Toshi / chat thinking.ds-loading-dot (real)The only place the bouncing dots belong: a conversational wait.

All four stop animating under prefers-reduced-motion (the shimmer becomes a flat #EEF2F6 and the bar a static 40% line).

Relationship to empty-state-product-demo

The real partials/empty-state-product-demo is a pre-onboarding marketing loop (three auto-playing scenes: WhatsApp, Toshi, connectors), not a per-component empty state. It stays as it is, for the one place it belongs: a brand-new school with nothing set up. Everything above is for "this list or card has no data yet" inside a working school, so the two don't compete. Worth confirming: the bulletins page still prints a bare "No records found" line — that's the kind of screen the migration should reach first.
