Email verification with a code and a link. The message gives both the 6-digit code and a Confirm email button, which opens a signed link. The sign-up tab accepts either. When the link is opened on another device, that device shows a confirmation page, and the original tab continues on its own.

Designed from main @ 3cf3025bf5b0, on top of #904's code flow. The email uses the Task B shell: 600px tables, system fonts, the PNG logo, hex colours only. Demo data only. Contrast is calculated from hex, not browser-measured.

Behaviour

  1. One message, two ways to confirm: the 6-digit code from #904 and a signed link (URL::temporarySignedRoute('register.verify.link', $expires, ['token' => …])). Both expire at the same time as the code, and using either one uses up both.
  2. Opening the link never signs that device in. It only marks the email as confirmed. That's why the other-device page asks you to continue on the original tab, or to sign in here.
  3. The original tab continues on its own: it checks GET /register/verify/status every 5 seconds while visible, and on visibilitychange. When the email is confirmed, it moves on to the next step (onboarding) with a "Email confirmed" toast. It stops checking after the code expires.
  4. Same browser: if the link is opened in the browser that holds the pending sign-up session, it goes straight to the next step. No confirmation page is shown.
  5. Link scanners: some mail systems open links automatically. The link therefore lands on a page with a Confirm email button that POSTs the token, so a plain GET never confirms by itself. (Not drawn: it looks like screen 3 before confirming, with one primary button.)
