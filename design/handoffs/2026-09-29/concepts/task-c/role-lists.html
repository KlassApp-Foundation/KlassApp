Role-scoped student lists

Designed from main @ a9013f74b384. Scoping follows app/Services/RosterScopeService.php. That service already enforces the pattern this matrix extends: a subject teacher's roster query selects only id, name, status, so every other column is never sent. The matrix turns that one special case into a column set for every role.

Column matrix

Default is in the list or profile payload. On request means the user taps "Show", which calls a separate endpoint that is policy-gated and written to the activity log. Never sent means the column is left out of the query's select. It is never hidden with CSS.

Things the repo contradicts or doesn't have

There's no Head teacher or Bursar role.The usergroups are SiteAdmin 1, SchoolAdmin 3, SchoolSubadmin 4, Teacher 5, Student 6, Parent 7, Librarian 8, OldStudent 9, Receptionist 10, Accountant 11 and Stock Keeper 12. "Bursar" is shown here as Accountant (11). "Head teacher" has no role, so it's shown as SchoolSubadmin (4) until you decide whether it needs one.
RosterScopeService rejects 4, 8 and 11.assertActorCanAccessSchool allows only usergroups 3 and 5, plus 1. The head teacher, librarian and bursar columns therefore need new scope branches before they can work. Parents stay on their own children relation and are never routed through the roster.
Class teacher and subject teacher are one role.Both are usergroup 5. They differ by the stream's class_teacher_id (with a fallback to the section's class teacher) versus a class_teacher_links row. The existing isSubjectTeacherOnly() is the right switch; keep it.
Bugs in the teacher student view.teacher/student/show heads the page "ID: {{ user id }}" (the database id, not the admission number). It also prints 01-01-1970 when there's no date of birth, and reads $user->userprofile->gender without optional(), so it crashes when there's no profile.
Two cells need your decision.First: can a class teacher see fee balances on request? Ugandan class teachers often chase fees, but many schools keep money with the bursar only. Second: can a subject teacher see special-needs notes on request? That helps lesson planning, but it widens access to health data. Both are marked "on request" until you rule.

List and student view by role

Only the columns in the matrix are drawn, and the student view opens on each role's default tab. Tabs a role can't see don't exist in the payload, so they aren't rendered as disabled.
